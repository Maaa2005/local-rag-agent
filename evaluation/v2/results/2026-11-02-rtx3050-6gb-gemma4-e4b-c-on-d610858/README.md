線は Issue #1 の 11/2 のコメントで測る前に決めた（`docs/v2-light-model-plan.md` §1 の線のまま、V の予算だけ 6,144 − 512 = 5,632 MiB、P は換算しない）。
測り方は `evaluation/gpu_local/`（コミット d610858）。回答の本文はリポジトリに入れていない。

## 結論

- **不合格**（2 回とも N 11/12、外したのは T4 と同じ N09）。線は動かしていない。
- 6GB のカードに載るかは問題ない。GPU の最大は 3,609 MiB で、予算に 2,000 MiB 残る。
- 1 回目は N 以外の線（V・P・Q）を全部通った。2 回目はホストのメモリが尽きて遅くなり、Q011 が検索の時間切れで答えられず、V（全問回答）・P・Q（M8）も落ちた。決まりどおり 2 回目を無効にもやり直しもしていない。
- G0（接続・権限・障害）は全項目 PASS。
- 換算の確かめ: 出力の速さは予測（T4 の 51.1 × 168/320 = 26.8 トークン/秒）の 1.53 倍と 1.45 倍で、決めた幅（0.75〜1.25 倍）を外れた。**帯域の比で換算する考え方は、このモデルでは見直しが要る**。

## 分かった事

1. **6GB の VRAM には余裕がある。** Windows の画面などで空きは起動前に 5,154 MiB だったが、最大 3,609 MiB で収まった。
2. **T4 は、このモデルでは帯域で頭打ちになっていない。** T4 の 51.1 トークン/秒は、GPU 側の重み 2.9GB を毎回読むとしても帯域の半分ほど。3050 は帯域が T4 の 0.53 倍なのに、速さは 0.80 倍だった。T4 の値に帯域の比を掛ける 8GB 換算（× 320/272）は、このモデルでは遅めに見積もる側に外れている見込み。RTX 4060 では測っていないので確かめてはいない。
3. **VRAM だけでなく本体のメモリ（RAM）も要る。** Gemma 4 E4B は重みのうち 2.2GB を CPU 側に置く。2 回目はホストの空きが 49MB まで減り、最初の文字までが 3 倍に延び、Qdrant への問い合わせが qdrant-client の既定の上限 5 秒を超えて 1 問落ちた。導入先の条件に RAM の余裕を入れる必要がある（必要量は測っていない）。

## 数えなかった試行

- 11:55: 索引の作成で qdrant-client が 5 秒で時間切れ（WSL の ext4 で Qdrant 側は 5.8 秒）。数える回の前で止まった。保存先を `/dev/shm` に変えた。
- 11:57: 入力長の測定（出力 1 トークン・数えない回）で Q029 が `run_failed`（理由の文字が空）。決まりどおり止めた。型名を残すよう `run_eval` を直して最初からやり直した。後の G0 と 2 回目から、同じ型（qdrant-client の 5 秒の時間切れ）と見ている。

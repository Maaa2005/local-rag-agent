## 結論

- 測ったすべての構成が不合格。8GB・12GB とも、合格の線を全部通る構成は見つからなかった。
- 一番近かったのは Gemma 4 E4B（Q4_K_M・考え OFF）に C（数の比べをコードで計算し、その結果を参照情報と質問の間に足す。結論はモデルが書く）を入れた構成。N だけ 11/12 で落ち、他の線（M6・M7・M8・P・V・G0）は全部通った。
- 確かめ用 48 問では C ON 39/48・C OFF 36/48（観測上 3 問多い）。ただし C が計算の結果を足した問で外れが残ったので、測る前に決めた決まりどおり「C が効いた」とは言わない。「効果が無い」とも言わない。一般化は未確認。

## 原因（分かった事）

- N の不一致は、規程の文が検索で取れていて結論の書式も正しいのに、数の判断を誤ったもの（3 候補 5 回の 29 件: 境目ちょうどの読み違い 16・境目の下/上の大小の比べ違い 13。`evaluation/v2/results/2026-10-24-n-error-classification/`）。
- モデルを替えても、考えさせても N は 9/12 を超えなかった。考え ON は OFF より悪かった。
- C は N で Gemma 4 E4B の外れ 4 問のうち 3 問（N04・N05・N11）を直し、OFF で合っていた問は落とさなかった（8GB・12GB とも同じ）。
- 残った N09 は「全労働日のうち出勤した日の割合」で決まる問。質問に日の値が 2 つあるため C は計算せず（保留）、モデルが誤った。C は 1 つの値を境目と比べる形だけを扱い、割合の計算は範囲の外。

## 確かめ用 48 問（補助の証拠・合否の線ではない）

- C が足したのに外れた 7 問の原因は未確定。手元に残したのは id と数だけで、問ごとの C の記録（抜き出した条件・判定）を残していないため。H10 の悪化も、C のせいか出力の揺れかは分けられていない。
- 開発用 N では C が足した問の割合が 12 問中 9（全 62 問では 10）、確かめ用では 48 問中 36。問の作り方で C の出番が大きく変わるので、実際の質問でどれだけ使われるかは未確認。

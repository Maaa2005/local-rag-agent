# 規程カード方式: 封を開ける前に固定する手順（案）

Issue #16。11/4 の二者協議（Codex gpt-6.1-sol と Claude・3 段）の結論を、Issue 本文の線に合わせて書いた。**案であり、下の「本人が決める事」が決まるまで封は開けない**。合格線は変えない。協議の時点で Issue 本文を渡せていなかったので、誤断定の線はここで Issue 本文（誤った断定 0）に合わせて直した。

## 流れ

1. **規程を開く前に、手順と道具を固定する**: 下書きのプロンプト全文・モデルと版・生成設定・見本とその順序・入力の範囲・分割の単位・カードにする対象の選び方・通信の再送の上限。下書きは対象ごとに 1 回。人の直しは原文を根拠に認め、全部の差分と理由を残す
2. **封の外で、動くかを確かめる**: 封を知らない別担当が、単位の換算・年の無い日付・時刻・例外・不明を含む新しい開発用の問を作る。線と同じ数え方（全体 90% 以上・各規程 80% 以上）を先に決め、届かなければ封を開けない。N 12 問と開発用 24 問は調整に使ったので、後戻りの確かめだけに使う
3. **評価の入口と抽出の条件を固定する**: 封用のカードの置き場を分け、`allow_draft=False`。規程ごとの集計を持ち、通常の回答（カードに合わなかった問）をコードが決めた数に入れない。未選択・読み込みの失敗・抽出の失敗を問ごとに残す。モデルの重みと量子化・llama.cpp の版・会話の形・考える機能の扱い・文法の渡し方・上限・時間切れ・再試行も固定する
4. **評価を流す人が規程だけを開いてカードを作り、人が確認する**: 確認者は問と正解を知らず、原文と適用範囲・式・単位・境目・例外・不明の時の結論を見比べられる人。署名・日時・原文の版と指紋・確認の履歴を残す。今の 12 枚は未確認のまま
5. **全 16 規程のカードか「作れない」の記録を固定してから、問を開く**: 作れない事を理由に、除外・差し替え・作り直しをしない。そのカードが無いまま流し、未達として数える。中身は評価が終わるまで実装担当へ戻さない
6. **各問 1 回で流して、Issue 本文の線で判定する**: 誤った断定 0・保留すべき 48/48 を保留・コードが決めた割合が全体 173/192 以上かつ各規程 10/12 以上・言い換えの対の両方が正しい 90% 以上。結果を見て直したら別の評価として新しい封を作る

温度 0 は再現の保証ではないので、別々に起動して 2 回という既存の N の線はそのまま別に測る。

指紋の不一致や情報の漏れは「作れない」と別で、その評価を無効として記録する。

## 手順で扱う危険

- **カードの選び方が結論の選択肢の完全一致に頼っている**（`rule_cards.select_card`）。問の選択肢を知らずに作ったカードは当たらないおそれがある。下の本人の判断 2 に関わる
- **llama.cpp #30256**: 考える文が出ると抽出の枠を食い、保留が増えるおそれ。手元の測定で確かめ、出るなら文法の渡し方を手順に入れて固定する（線は変えない）
- **抽出の失敗は保留のまま**。Issue 本文の「不明なら保留」どおり。コードが決めた割合が足りなければ未達にする

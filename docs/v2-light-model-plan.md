# v2 軽量モデル実験計画

作成: 2026-10-19 / 状態: 実行前（合否の線はこの文書で固定し、測った後に動かさない）

## 0. 目標（2026-10-19 本人決定）

- 最終目標は「学校 PC（GPU 6GB）で動くこと」ではなく、**GPU 8〜12GB の PC で、1 問 15 秒以内に答える、実際に使える RAG**。
- 重すぎると一部の人しか使えないので、蒸留・小型化された賢いモデルを中心に試す。
- 2 つの構成で合否を出す。
  - **下限構成（8GB カード）**: 例 RTX 4060 8GB。ここで通る構成を既定にする。
  - **上限構成（12GB カード）**: 例 RTX 3060 12GB。下限より賢くなる場合だけ採る。
- 6GB 前提の作業（本番 compose への offload 設定の移植・e886667）は優先度を下げる。下限が 8GB になったため。

## 1. 合否の線（実行前に固定）

候補ごとに G0 → Q → N → P → V の順に見る。G0 で落ちた候補はその先を測らない。

### G0. 接続・権限・障害の回帰（Issue #7 の A 一式）

`evaluation/colab/rag_connection_check.py` を候補のモデル・実行系で流し、全項目 PASS（2 問回答・権限外が出ない・上位ユーザーには出る・固まる→戻る・停止・監査に本文 0）。

### Q. 回答の質（`evaluation/CRITERIA.md` の値をそのまま使う）

`evaluation/run_eval.py` で `dataset.jsonl` 50 問を流す。

| 指標 | 線 | 扱い |
|---|---|---|
| M7 権限フィルタ正答率 | = 1.00 | 必須 |
| M4 Faithfulness | ≥ 0.90 | 必須 |
| M6 Correctness | ≥ 0.80 | 合否 |
| M8 適切な拒否率 | ≥ 0.95 | 合否（拒否すべき 16 問なので、実質 16/16） |
| M1 Recall@5 / M2 MRR | ≥ 0.80 / ≥ 0.60 | 埋め込み・リランカーを変えたときの合否 |
| M3 / M5 | ≥ 0.70 / ≥ 0.80 | 記録（比較用） |

7/28 の「意味的正確性 83.3%」は 6 問・別モデル・別の流れでの数字なので、比較の基準線にはしない。基準線は §4 Step 1 で今の予備モデルを同じ 50 問に流して作る。

### N. 数値・境界の正確さ（新設）

7/28 の検証で、キーワードが全部入っていても規則の当てはめが間違う例が出た（5,000 円の領収書に「1 万円以上なら部門長承認」を適用）。M6 はこれを拾えない。

- `evaluation/v2/numeric_boundary.jsonl` を新しく作る。架空コーパスの金額・日付・割合の規則から 12 問。規則の境界の下・ちょうど・上を必ず含める。
- 各問は「正しい結論（承認要否・期限日・金額）」を 1 つ持ち、完全一致で採点する。
- 線: **規則の誤適用 0 件**（12/12）。F7 数値ガードの合否にもそのまま使う。

### P. 速さ

| 指標 | 対象機での線 | T4 で測るときの線 | 出どころ |
|---|---|---|---|
| P1 最初の文字までの中央値 | ≤ 5.0 秒 | ≤ 5.0 秒 | CRITERIA §7 のリリース条件 |
| P3 回答完了までの中央値 | ≤ 15.0 秒 | **≤ 12.5 秒** | 本人の「15 秒まで」・CRITERIA P3 |
| P2 最初の文字までの 95% 点 | ≤ 12.0 秒 | ≤ 12.0 秒 | 記録（比較用） |

T4 では P3 の線を 12.5 秒に締める。文章を作る速さはメモリ帯域で決まり、RTX 4060 8GB の帯域（272 GB/s）は T4（320 GB/s）より約 15% 低い。そのため T4 の結果に 320÷272 ≈ 1.18 倍を掛けて 15 秒に収まる線にした。P1 は入力の処理が中心で計算力で決まり、4060 の計算力は T4 より高いので、P1 には補正を掛けない。

### V. GPU メモリ

- 測り方: 試験の間ずっと `nvidia-smi` を 1 秒ごとに記録し、最大値を取る。LLM の重み、実際に使う文脈長での KV キャッシュ、GPU に載せた埋め込みとリランカーを全部含める。
- 線: 下限構成 **≤ 7.5 GB**、上限構成 ≤ 11.5 GB。家庭用カードは画面表示にも数百 MB 使うため、カード容量より 0.5 GB 低くした。
- vLLM は `gpu_memory_utilization` で上限を掛けられる。llama.cpp は上限を掛けられないので、実測の最大値で判定する。

## 2. 測る前に直す所（Step 0）

1. **採点役を全候補で 1 つに固定する。** 今の `run_eval.py` は `--judge vllm` が既定で、候補自身が自分の答えを採点する。採点は答えを作るのと同じ処理の中で行われるので、採点役と候補が GPU を取り合い、V と P の数字も汚れる。
   - 回答だけ流して質問ごとの結果を JSON に保存する（`--no-judge` に保存を足す）。
   - 保存した答えを、採点役だけを載せた別の実行で採点する（`--judge-from <結果.json>` を足す）。
   - 採点役は候補に入れない別の系統の 14B 級 4bit を第一案にする。T4 で起動するかは未確認。採点役は全候補の採点が終わるまで変えない。
2. **リランカーと埋め込みの置き場所を設定で選べるようにする。** 今は `backend/app/services/reranker.py:15` と `embedder.py:12` が `device="cpu"` 固定。#7 の B では、CPU のリランクが 1 回で検索の上限 30 秒を超えた。`rerank_device`・`embed_device` を設定に足し、既定は `cpu` のままにして今の挙動を変えない。テストを足す。
3. **N の 12 問を作る。** 作ったら `tests/test_dataset_corpus.py` と同じ方法で、出典が実在するか・答えが本文にあるかを確かめる。
4. **GPU メモリの記録をノートに足す**（1 秒ごとの `nvidia-smi` を別スレッドで記録し、最大値を結果に書く）。

## 3. 候補（すべて未計測）

### LLM

| 構成 | 候補 | 見どころ | 注意 |
|---|---|---|---|
| 基準線 | sarashina2.2-3b-instruct | #7 A で PASS 済み（生成の中央値 7.85 秒・T4） | 質は 50 問で未測定 |
| 下限 | LFM2.5-1.2B-JP | JMMLU 50.7（公式） | LFM Open License の商用・再配布の条件を要確認 |
| 下限 | TinySwallow-1.5B | TAID で蒸留 | — |
| 下限 | 4B 級の日本語対応モデル（具体名は Step 2 の前に 2 つまで選ぶ） | 1〜3B より賢い見込み | — |
| 下限 | LLM-jp-4 8B thinking（GGUF Q4_K_M） | MT-Bench JA 7.57（公式） | 考える過程の分だけ遅い。考えを切る・上限を付ける設定で P3 に収まるか |
| 下限 | Gemma 4 E2B（今の第一候補） | — | T4 の vLLM では起動しない（head 512・compute 8.0 以上が要る）。T4 で測れないのは「対象機で不可」ではなく「未確認」として記録する |
| 上限 | Nemotron Nano 9B JP | Nejumi 4 で 10B 未満 1 位（公式） | NVIDIA Open Model License を要確認 |

外す物:

- LLM-jp-4 32B MoE: 軽くない。
- Qwen3-Swallow 30B-A3B: 4bit でも重みが約 17GB で 12GB に載らない見込み。GGUF では考える過程の切り替えに問題がある。

### 実行系

- 今は vLLM。llama.cpp の `llama-server`（GGUF）や Ollama も OpenAI 互換の API を出す。こちらのコードは vLLM 専用の引数を使っていない（grep で 0 件）ので、`VLLM_BASE_URL` を差し替えれば動く見込み。ただし未試験。
- 「誰でも使える」には導入の手軽さが効く。上位 1 候補で vLLM と llama-server の両方を測り、P・V・導入の手数で決める。

### 埋め込み・リランカー

- 埋め込み: 今の `intfloat/multilingual-e5-large`（1024 次元）と ruri-v3（30m / 70m / 130m / 310m）を比べる。切り替えるには `embed_model`・`vector_size`・前置き文字列を設定で変え、全文書を索引し直す。M1・M2 で判定する。
- リランカー: `BAAI/bge-reranker-v2-m3` を GPU に載せた場合と、japanese-reranker-tiny-v2 / xsmall-v2（MIT）を比べる。tiny が 30 候補で約 0.14 秒という数字は、公式表からの推定で未計測。
